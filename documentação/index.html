RN001

Controle de acesso ao formulário de denúncia

Esta regra define o controle de acesso à funcionalidade de registro de denúncia no portal.

  • O formulário de registro de denúncia somente será exibido para usuários autenticados (com sessão ativa no sistema).
  • Ao acessar a página /denuncia/ sem estar autenticado, o sistema não exibirá o formulário. Em seu lugar, será apresentado um bloco informativo com ícone de cadeado e a seguinte mensagem orientativa:
Mensagem de Restrição
"Para iniciar o preenchimento da denúncia, por favor, faça login na plataforma."
  • Será exibido um botão "Fazer Login" que redirecionará o usuário para a página de login, preservando o endereço de destino no parâmetro ?next= da URL, para que após o login o usuário seja retornado automaticamente à página de denúncia.
RN002

Opção de denúncia anônima

Esta regra define o comportamento da opção de anonimato no formulário de denúncia.

  • Mesmo que o usuário esteja autenticado, o sistema deve oferecer a opção de realizar a denúncia de forma anônima, por meio de uma caixa de seleção (checkbox) presente no formulário, com o seguinte texto:
Texto da Opção
"Desejo fazer esta denúncia de forma anônima (não vincular meu usuário)"
  • Quando esta opção estiver marcada, o registro da denúncia não deverá ser vinculado ao usuário logado.
  • O sistema deve registrar a denúncia sem associação de identidade, garantindo o sigilo absoluto do denunciante.
RN003

Unicidade de usuário no cadastro

Esta regra é utilizada para garantir a integridade e unicidade dos nomes de usuário na plataforma.

  • Ao submeter o formulário de cadastro, o sistema deve verificar se o username informado já existe na base de dados.
  • Caso o nome de usuário já esteja cadastrado, o sistema deve bloquear o registro e retornar a tela de cadastro com a seguinte mensagem de erro:
Mensagem de Validação
"Usuário já existe"
  • Apenas após a confirmação de que o username é único, o sistema poderá criar a conta e autenticar o usuário automaticamente.
RN004

Redirecionamento pós-autenticação

Esta regra define os comportamentos de redirecionamento do fluxo de navegação após as ações de login, logout e cadastro.

Regras específicas de redirecionamento:

  • Após o login bem-sucedido: caso exista parâmetro next na requisição, redireciona o usuário para a URL indicada neste parâmetro. Caso contrário, redireciona para a página inicial (portal:home).
  • Após credenciais inválidas: retorna à tela de login com o erro: "Usuário ou senha inválidos."
  • Após o cadastro bem-sucedido: autentica o usuário de forma automática e o redireciona diretamente para a página inicial.
  • Após o logout: encerra a sessão ativa e redireciona o usuário para a página inicial.
RN005

Recursos de acessibilidade

Esta regra define os recursos de acessibilidade que devem estar disponíveis e operacionais em todas as páginas do portal.

  • O portal deve apresentar, em todas as páginas, uma barra de acessibilidade no topo da tela com as seguintes opções:
    • Aumentar texto (A+): ao ser acionada, aumenta a fonte global para 120%.
    • Restaurar texto (A): restaura a fonte ao tamanho padrão (100%).
    • Alto Contraste: aplica filtro de inversão de cores e rotação de matiz no corpo da página. Uma segunda ativação desliga o filtro.
  • A barra de acessibilidade deve exibir o seguinte texto institucional: "Portal de Utilidade Pública — Instituto Federal do Tocantins".
RN006

Filtros de delegacias e canais oficiais

Esta regra define a funcionalidade e o comportamento dos filtros interativos na página de delegacias.

  • A página de delegacias deve apresentar um painel lateral de filtros que permita refinar a listagem pelos seguintes critérios de busca:
    • Tipo de órgão: combo contendo as especialidades (Cibernéticos, Idoso, Procon, Canal Online).
    • Busca por nome: campo de texto livre que filtra os itens pelo nome digitado.
    • Município: combo com os municípios do Tocantins cadastrados (Palmas, Gurupi, Araguaína, etc.).
  • Os filtros devem ser processados dinamicamente via JavaScript client-side, sem a necessidade de recarregar a página.
RN007

Alerta global de segurança

Esta regra define a presença e obrigatoriedade de exibição do alerta global antifraude em toda a plataforma.

  • Em todas as páginas do portal deve ser exibida uma faixa de alerta fixada abaixo do cabeçalho, com o texto:
Alerta Antifraude Fixo
"Atenção: Nenhuma instituição bancária ou órgão público solicita senhas, códigos ou transferências por telefone ou mensagem. Desconfie sempre e confirme por outros canais antes de qualquer ação."
  • Esta faixa é injetada via template base (`base.html`), garantindo consistência técnica em qualquer nova rota criada no portal.

Função 3

Acesso (URL)

/denuncia/

Permissão

Restrito (Exibe informativo se deslogado)

Template

portal/denuncia.html

Objetivo

Permitir o registro estruturado de um crime digital sofrido ou presenciado pelo cidadão.

Lógica de Processamento

A página verifica se o usuário está autenticado no Django. Se autenticado, apresenta o formulário de cadastro. Se deslogado, oculta os campos e apresenta card para realizar login com retorno dinâmico (parâmetro next), conforme a RN001.

Função 6

Autenticar Usuário (Login)

Acesso (URL)

/accounts/login/

Permissão

Público

Template

accounts/login.html

Objetivo

Validação da identidade do cidadão na base de dados do Django para iniciar uma sessão de usuário ativa.

Lógica de Processamento

O formulário envia os campos username e password em requisição POST. O sistema autentica via Auth backend. Em caso de sucesso, redireciona o usuário (obedecendo à regra de parâmetro next se fornecido, RN004). Em caso de erro, retorna erro de validação.

Função 7

Cadastrar Usuário (Registro)

Acesso (URL)

/accounts/register/

Permissão

Público

Template

accounts/register.html

Objetivo

Permitir a criação de contas de acesso à plataforma pelo cidadão.

Lógica de Processamento

O formulário verifica a exclusividade do campo username no banco de dados (RN003). Caso esteja liberado, cria o registro do usuário com a senha criptografada via Hash e efetua o login automático direcionando para a página principal (portal:home).

Função 8

Encerrar Sessão (Logout)

Acesso (URL)

/accounts/logout/

Permissão

Restrito a Logados

Objetivo

Encerrar a sessão ativa do usuário com segurança.

Lógica de Processamento

Aciona a função logout() do Django, invalidando o token de sessão atual e redireciona o usuário para a página de login ou página inicial conforme a regra RN004.
